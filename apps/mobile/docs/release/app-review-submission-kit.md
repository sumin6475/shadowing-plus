# Saylo — App Review submission kit (2026-09-10)

Everything App Review needs that lives in **App Store Connect, not in the repo**.
Blockers B4 (demo account) and B5 (age rating) from
`app-store-submission-audit.md` are closed by working through this file.

> These two cannot be done from the codebase: one requires creating an account
> and typing a password, the other requires answering a form in App Store
> Connect. Everything below is written so it is copy-paste, not judgement.

---

## 1. Demo account (Guideline 2.1)

Saylo is fully sign-in gated (`Stack.Protected` in `src/app/_layout.tsx`), so a
reviewer who cannot sign in files a 2.1 rejection without opening the app.

### 1.1 Create it

Sign up **inside the app** (Profile → the normal email flow) with a dedicated
address you control, e.g. `review@<your-domain>` or a `+review` alias. Use a
throwaway password you are willing to put in plain text in App Store Connect.
Confirm the email so the account is live before you submit.

### 1.2 Seed it — 10 minutes, in the app

An empty Today screen reads as a broken app, and the reviewer has no way to
produce content quickly (they will not record speech into a review device). Do
these in order, in the app, signed in as the review account:

1. **Allow OpenAI processing** when the consent alert appears — otherwise every
   AI surface is inert and the reviewer sees error states.
2. Studio → create **2 topics** with **1 story each** (e.g. "My work", "A recent challenge").
3. Speak → record **2 short sessions** (30–60 s) against those stories, and let
   the feedback finish so `talk-diagnose` output exists.
4. Save **8–12 phrases** from those sessions and from Phrase capture.
5. Review a few phrases so Today shows a **partly finished** queue (e.g. `3 / 7`),
   not `0 / 7`.
6. Set a display name and a profile photo, so the avatar isn't a bare initial.
7. Settings → **Show tips again**, so the reviewer lands on the first-run tour.

This is the same account the screenshots are captured from
(`app-store-screenshots-plan.md` §5.1) — do it once, use it twice.

### 1.3 App Review Notes — paste this

```
DEMO ACCOUNT
Email:    <review account email>
Password: <password>

WHAT THE APP DOES
Saylo is an English speaking-practice app. You record yourself talking about
your own story, the app writes down what you said, points out one weak moment,
and turns the fix into a phrase you review over the following days.

MICROPHONE AND SPEECH RECOGNITION (please read before testing)
- The microphone is the core feature. Tap the mic circle in the tab bar, or
  "Speaking" on the Today screen, and talk for 20-30 seconds.
- Speech is transcribed by Apple's ON-DEVICE speech recogniser
  (requiresOnDeviceRecognition = true). No audio is sent to any server.
- Recordings are written to the app container and are never uploaded. They can
  be deleted individually from each session screen.
- A red "Listening" indicator with a live waveform is shown for the whole time
  the microphone is active.

THIRD-PARTY AI (Guideline 5.1.2(i))
- On first launch the app asks permission before sending anything to OpenAI,
  names OpenAI in the prompt, and states what is sent.
- Only text you produced, or a photo you explicitly choose, is sent. Speaking
  recordings are never sent.
- The permission can be revoked at any time: Profile > Privacy > "Allow OpenAI
  processing". With it off, no AI feature transmits anything.

ACCOUNT DELETION (Guideline 5.1.1(v))
Profile > Delete account. It deletes the account and all associated data
immediately, server-side, and clears on-device recordings.

CAMERA
Optional. Used as a live "mirror" while speaking (never recorded), to read
English text off a photo you choose, and for a profile photo.

NO ACCOUNT-BASED FEATURES ARE LOCKED, and the app contains no purchases.
```

## 2. Age rating questionnaire (mandatory since 2026-01-31)

App Store Connect blocks new submissions until the updated questionnaire is
answered. Saylo's honest answers:

| Topic | Answer | Why |
|---|---|---|
| Cartoon / fantasy / realistic violence | **None** | No such content |
| Sexual content, nudity | **None** | — |
| Profanity or crude humour | **None** | The learner may say anything into their own mic, but nothing is published or shown to anyone else |
| Horror / fear themes | **None** | — |
| Alcohol, tobacco, drug use or references | **None** | — |
| Simulated gambling, contests | **None** | — |
| Medical / treatment / wellness information | **No** | It teaches speaking, gives no health guidance |
| **AI-generated content** | **Yes** | Feedback, phrase suggestions and language help are generated by OpenAI from the learner's own text. It is task-scoped coaching output, not an open-ended chatbot, and there is no free-form conversation partner |
| **User-generated content shared with others** | **No** | Everything a learner creates is private to their account. There is no feed, no profiles, no sharing, no messaging — so no moderation/reporting/blocking obligation under 1.2 |
| Unrestricted web access | **No** | No general-purpose browser. Two browser uses, both Apple's in-app sheet with no address bar to type into: the OAuth sign-in, and a phrase's **Open YouGlish**, which opens one fixed `youglish.com/pronounce/<phrase>` page (added 2026-09-24). Links on that page can be followed (e.g. to YouTube), so revisit this answer if the app ever gets a URL field or opens arbitrary sites |
| In-app purchases / ads | **None** | — |
| **Minimum age requirement** | **Set 13+** | The privacy policy and terms already say the app is not directed at under-13s. Use the new "set a higher rating to reflect your app's minimum age requirement" control so the store listing matches the policy instead of contradicting it |

## 3. App Privacy label — must match the shipped manifest

These answers mirror `expo.ios.privacyManifests` in `app.json` exactly. A
mismatch between the label and the manifest is its own rejection.

**Data used to track you: NONE.** (No IDFA, no ATT prompt, no cross-app tracking,
`NSPrivacyTracking = false`.)

**Data linked to you:**

| Category | Item | Purpose |
|---|---|---|
| Contact Info | Email Address | App Functionality |
| Contact Info | Name | App Functionality |
| User Content | Photos or Videos (profile photo only) | App Functionality |
| User Content | Other User Content (phrases, stories, notes, transcripts) | App Functionality |
| Identifiers | User ID (opaque account id) | Analytics |
| Usage Data | Product Interaction | Analytics |
| Diagnostics | Crash Data | App Functionality |

**Data not collected — say NO explicitly:**

- **Audio Data.** Speaking recordings never leave the device. `verify:release-config`
  fails the build if `NSPrivacyCollectedDataTypeAudioData` is ever added without
  this document and the privacy policy changing first.
- Precise or coarse location, contacts, health, financial info, browsing history,
  search history, advertising data, device ID.

## 4. Beta App Review (before any external TestFlight tester)

External testing needs a Beta App Description and Beta App Review Information —
the same demo account and the same microphone explanation as §1.3. One extra
line testers need:

```
TestFlight builds expire after 90 days. Speaking recordings are stored only on
your device, so they are lost when the build expires or you delete the app.
Export anything you want to keep first.
```

## 6. Which build goes where

Two EAS profiles upload to the **same** App Store Connect app and share one
build-number counter, so App Store Connect lists their builds side by side —
"1.0.0 (23)", "1.0.0 (24)" — with nothing saying which profile made which.

| Profile | Library / Recommendations | Use for |
|---|---|---|
| `testflight` | shown | your own phone, and the internal TestFlight group only |
| `production` | hidden | external testers (Beta App Review) and App Review |

A `testflight` build must never reach Beta App Review or App Review: Library is
unfinished, and shipping it is the Guideline 2.1 exposure blocker B6 closed.

**Before picking a build in App Store Connect**, look up which profile made it,
and choose a number whose profile is `production`:

```bash
npx eas-cli build:list --platform ios --limit 5
```

On the phone, the quick tell is Settings: a Library card there means a
`testflight` (or dev) build.
