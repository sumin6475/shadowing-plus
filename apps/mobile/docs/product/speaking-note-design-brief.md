# Speaking Note 상세 — 디자인 기획서 (세부)

작성 2026-09-09 · 대상 화면 `SpeakingNoteScreen` (`apps/mobile/src/screens/studio-information.tsx`)
현재 구현: PR #5 (`feat/studio-note-loop`) — 구조는 맞고 **비주얼을 다시 잡아야 한다**
목적: 이 문서 하나로 다른 도구에서 화면을 디자인할 수 있게 하는 것. 데이터·상태·제약은 전부 실측이고, 비주얼 결정은 열어둔다.

---

## 1. 이 화면은 무엇인가

**말할 내용 하나를 쓰고, 그걸 소리 내어 연습하고, 고칠 점을 받아 다시 연습하는 자리.**
Topic → Situation → **Speaking Note** → Practice Attempt 위계의 잎사귀이자, 앱에서 유일하게 "쓰기"와 "말하기"가 같은 화면에 있는 곳이다.

사용자가 여기서 하는 일은 넷이다. 빈도순.

1. **연습을 시작한다** — 가장 잦다. 화면에 들어온 이유의 대부분.
2. **연습을 끝내고 돌아온다** — 방금 받은 고칠 점 한 가지를 읽고, 바로 다시 말한다. **이 화면은 연습의 착지점이기도 하다.**
3. **내용을 고친다** — 한두 줄 덧붙이거나 표현을 바꾼다. 처음부터 길게 쓰는 일은 드물다.
4. **표현을 연결한다** — Phrase Bank에서 이 노트에 쓸 문장을 끌어온다.

2번이 이번 개편의 핵심이다. 이전에는 연습이 끝나면 Studio 홈으로 튕겨서 루프가 끊겼고, 지금은 이 화면으로 돌아온다. **"돌아온 직후"가 별도의 화면 상태로 설계돼야 한다.**

## 2. 지금 디자인이 실패하는 지점 (이 문서를 쓰는 이유)

구조는 맞다. 위계도 산다. 문제는 전부 시각적이다. 스크린샷 기준으로 구체적으로:

| # | 문제 | 왜 문제인가 |
|---|---|---|
| 1 | **본문 아래 거대한 빈 구멍** | 본문 입력 영역에 최소 높이가 걸려 있어서, 짧은 노트에서는 본문과 액션 칩 사이가 통째로 비어 보인다. 여백이 아니라 **고장으로 읽힌다.** |
| 2 | **본문이 편집 가능해 보이지 않는다** | 필드 어포던스가 0이다. 위쪽 헤어라인 하나뿐이라 정적 텍스트로 보인다. "열린 편집 영역"이 목표였지만 지금은 그냥 **읽기 화면**처럼 보인다. |
| 3 | **제목 / 목표 / 본문의 층이 3개가 아니라 2개로 읽힌다** | 목표 17pt와 본문 16pt는 육안으로 같다. 굵기 차이만으로는 "이건 한 문장 요약, 이건 본문"이 안 갈린다. |
| 4 | **화면 아래 절반이 균질하다** | 액션 칩 / Linked Phrases / Previous Attempts가 비슷한 무게로 흩어져 리듬이 없다. 눈이 멈출 곳이 없다. |
| 5 | **Previous Attempts가 정보를 안 준다** | 실측에서 모든 행이 `No fix suggested · 0:00`이다. Linked Phrases와 같은 면적을 먹으면서 신호는 0. **빈 이력의 시각 처리가 따로 필요하다.** |
| 6 | **하단 고정 CTA가 화면에서 제일 무겁다** | 풀블리드 채움 캡슐 + 상단 헤어라인이 항상 떠 있다. 가장 중요한 액션인 건 맞지만, 지금은 **콘텐츠보다 UI가 무겁다.** |
| 7 | **액센트 컬러를 부차적인 것에 다 써버렸다** | 브레드크럼, 칩 2개, 섹션 액션이 전부 코발트 계열이다. 정작 주 액션(하단 CTA)도 코발트라 **우선순위가 색으로 안 읽힌다.** |
| 8 | **placeholder가 콘텐츠처럼 보인다** | 목표가 비었을 때 뜨는 안내 문구가 본문과 비슷한 회색이라 사용자가 쓴 글로 오인된다. |
| 9 | **저장 상태 표시가 떠 있다** | 헤더 우측 텍스트 하나가 정렬 기준 없이 놓여 있다. |

**요약: 위계는 정보 구조로만 존재하고, 타이포·간격·색으로는 표현되지 않았다.**

## 3. 진입 경로와 나가는 길

- **들어옴**
  - Studio 홈 `Recent notes` 행
  - Studio 홈 `Continue practicing` 카드
  - Situation 상세 `Speaking Notes` 행
  - **연습 종료 후 자동 복귀** ← 신규. `justPracticed` 플래그를 달고 들어온다
- **나감**
  - 뒤로 (BackBar / 왼쪽 엣지 스와이프) → 이전 화면
  - 연습 시작 → 녹음(Talk) 전체화면
  - 브레드크럼 탭 → Organize 바텀시트
  - 표현 연결 → Link phrases 바텀시트

## 4. 정보 위계 (고정)

| 순위 | 블록 | 역할 | 비중 |
|---|---|---|---|
| 1 | **노트 본체** (제목·목표·본문) | 사용자가 쓴 것. 화면의 주인 | 첫 화면의 60% 이상 |
| 2 | **연습 시작** | 유일한 주 액션. 어디서든 닿아야 함 | 항상 접근 가능 |
| 3 | **Linked Phrases** | 말할 때 꺼내 쓸 재료 | 보조 |
| 4 | **Previous Attempts** | 조용한 이력 + 마지막 고칠 점 | 참고. 단, 연습 직후엔 승격 |

4번의 무게가 **상태에 따라 바뀌는 것**이 이 화면의 특징이다. 평소엔 가장 조용하고, 연습에서 막 돌아왔을 땐 가장 먼저 읽혀야 한다.

## 5. 들어가는 내용과 실제 데이터

전부 지금 코드에서 실제로 내려온다. **괄호와 ⚠️는 실측 주의사항이며 디자인에 직접 영향을 준다.**

### 5.1 헤더

| 내용 | 소스 | 실측 주의 |
|---|---|---|
| 소속 경로 | `note.topicName` / `note.situationTitle` | `IDEAS / SOMETHING I LEARNED` 수준. ⚠️ **Situation이 없으면 `Unsorted`.** 흔하다 |
| 저장 상태 | 화면 상태 | `Saving…` / `Saved ✓` / `Not saved · Retry` / 없음(idle). **네 상태 전부 그려야 함** |

- 브레드크럼은 **탭 가능**하다 (Organize 시트). 지금은 셰브론 하나로만 표시된다.
- ⚠️ 화면 제목이 따로 없다. BackBar에 타이틀을 넣지 않는 것이 현재 결정.

### 5.2 노트 본체 — 세 층

| 층 | 소스 | 실측 주의 |
|---|---|---|
| 제목 | `note.title` | 자유 입력. 실측은 짧다: `30-second version`, `Interview version`. ⚠️ **길어질 수 있음(2줄 상정)** |
| 목표 | `note.goal` | 한 문장. ⚠️ **비어 있는 경우가 많다.** ⚠️ Quick Note로 만든 노트는 **제목과 목표가 같은 문자열**일 수 있다 (`quickTitleFromBody`가 둘 다 만든다) |
| 본문 | `note.body` | ⚠️ **산문이 아니다.** 실측은 줄바꿈된 개요다:<br>`The starting point` / `What I learned` / `What changed` / `Why it matters to me`<br>4~6줄짜리 비트 목록이 전형. 길게 쓰는 사람도 있음 |

세 층 모두 **인라인 편집**이다. 라벨을 붙이지 않고 자리·무게·서체로만 구분한다 (PRD: "Apple Notes에 가까운 열린 편집 영역").

⚠️ **제목·목표가 같은 문자열로 중복 표시되는 케이스를 반드시 그려볼 것.** 지금 디자인에서 제일 이상해 보이는 상태다.

### 5.3 액션

노트에 **무언가를 추가하는** 동작들. 현재 2개.

| 액션 | 하는 일 |
|---|---|
| 생각 추가 | 본문 입력에 포커스를 준다 |
| 표현 연결 | Link phrases 바텀시트를 연다 |

- 과거엔 4개였다. `How can I say this?`는 표현 연결과 같은 시트를 열었고, `아이디어 녹음`은 하단 CTA와 같은 호출이었다. **중복은 이미 걷어냈으니 다시 늘리지 말 것.**
- 이 두 개는 주 액션이 아니다. 하단 CTA와 시각적으로 경쟁하면 안 된다.

### 5.4 Linked Phrases

| 내용 | 소스 | 실측 주의 |
|---|---|---|
| 표현 원문 | `phrase.text` | 영어 한 문장. `What I'm trying to do is...` 길이 |
| 번역 | `phrase.translation` | ⚠️ **비어 있을 수 있음.** 학습자 모국어(한국어만이 아님 — ko/es/ru/en) |
| 학습 상태 | `phrase.learningStatus` | `new` / `recognizing` / `practicing` / `ready` 4단계 |

- ⚠️ **실측 개수는 0~2개.** 수십 개가 되는 화면이 아니다. Situation 상세와 다르다
- 이 화면에서 표현을 편집·삭제하지 않는다. **연결/해제만** (바텀시트 안에서)
- 섹션 헤더 우측에 연결 액션 1개

### 5.5 Previous Attempts

| 내용 | 소스 | 실측 주의 |
|---|---|---|
| 날짜 | `attempt.createdAt` | `Aug 17` 형식 |
| 고칠 점 | `attempt.repairSuggestion` | ⚠️ **현재 100% 비어 있다.** 마이그레이션 027이 오늘까지 누락돼 몇 주간 AI 피드백이 하나도 저장되지 않았다. 앞으로 채워진다 |
| 길이 | `attempt.durationSeconds` | ⚠️ **`0`이 흔하다.** 실측에서 `0:00`, `0:01`이 다수 |
| 전사 | `attempt.transcript` | 있음. **현재 이 화면에서 안 씀** |

- 최대 20건 로드, 기본 3건 노출, 나머지는 접힘
- 고칠 점이 있는 행은 **탭해서 펼친다.** 없는 행은 탭 불가
- **연습 직후 복귀하면 최신 행이 펼쳐진 채로 들어온다**
- 가장 최근의 고칠 점 하나는 목록 위로 끌어올려 따로 보여준다

## 6. 인터랙션 사양 (구현 완료 — 디자인이 맞춰야 할 것)

### 6.1 자동 저장

- **수동 저장 버튼 없음.** 타이핑이 멈추고 800ms 뒤에 저장, 화면을 떠날 때 한 번 더 저장
- 헤더 우측은 **표시 전용**: `Saving…` → `Saved ✓`. 실패하면 `Not saved · Retry`(탭 가능)
- ⚠️ 제목이 비면 저장하지 않는다 (이름 없는 노트는 다시 찾을 수 없으므로)
- **디자인 과제**: 이 표시가 눈에 띄되 방해하지 않아야 한다. 지금은 그냥 떠 있는 텍스트다

### 6.2 키보드

- 세 필드 모두 인라인 편집이라 키보드가 자주 올라온다
- **키보드가 올라오면 하단 고정 CTA는 숨는다.** 내려가면 다시 나타난다
- **디자인 과제**: 이 등장/퇴장이 튀지 않아야 한다

### 6.3 연습 루프

```
노트 → [연습 시작] → 녹음 전체화면 → 종료
                                      ↓
                        같은 노트로 복귀 (justPracticed)
                                      ↓
                     최신 시도가 펼쳐진 채 · 고칠 점 노출
                                      ↓
                              [다시 연습]
```

**디자인 과제**: 복귀 직후 상태를 평상시와 다르게 그릴 것. 방금 받은 고칠 점이 화면에서 가장 먼저 읽혀야 하고, 두 번째 시도까지의 거리가 짧아야 한다.

### 6.4 하단 고정 CTA

- 노트 어디를 보고 있든 **연습 시작이 항상 닿아야 한다**
- 이게 이 화면의 유일한 주 액션이다
- **디자인 과제**: 항상 떠 있으면서 콘텐츠보다 가벼워 보이게 하는 것. 지금은 반대다

## 7. 필요한 컴포넌트

### 7.1 새로 필요하거나 다시 정의할 것

| 컴포넌트 | 하는 일 | 그려야 할 상태 |
|---|---|---|
| **브레드크럼** | Topic / Situation + 이동 어포던스 | Situation 있음 / `Unsorted`, 눌림 |
| **저장 상태 표시** | 자동 저장 피드백 | idle / saving / saved / error(탭 가능) |
| **제목 입력** | 인라인, serif | 1줄 / 2줄 / 비어 있음(placeholder) |
| **목표 입력** | 인라인, 한 문장 | 값 있음 / 비어 있음 / **제목과 동일** |
| **본문 입력** | 인라인, 열린 편집 영역 | 짧음(1줄) / 개요 4~6줄 / 길다 / 비어 있음 |
| **보조 액션** | 추가 동작 2개 | 기본 / 눌림 |
| **섹션 헤더** | 블록 제목 + 우측 액션 1개 | 액션 있음 / 없음 |
| **표현 행** | 표현 + 번역 + 상태 | 번역 있음 / 없음, 상태 4종 |
| **시도 행** | 날짜 + 요약 + 길이 | 고칠 점 있음(탭 가능·펼침) / 없음, 길이 0 |
| **고칠 점 블록** | 이번에 고칠 것 하나 | 목록 위 요약형 / 행 안 펼침형 |
| **하단 고정 CTA** | 연습 시작 | 기본 / 눌림 / 키보드로 숨김 |
| **블록 비었을 때** | 안내 문구 | Linked Phrases · Previous Attempts 각각 |

### 7.2 이미 있어서 그대로 쓸 것

`design-system/ios-motif-spec.md`와 `apps/mobile/src/design/ui.tsx` 기준. 재정의하지 말 것.

- `Screen` — 스크롤 컨테이너, 상단 frost, 안전영역
- `BackBar` — 뒤로 가기 + 우측 슬롯
- `Sheet` — 바텀시트 (Organize / Link phrases)
- `Pill` — 캡슐 버튼 3사이즈(28 / 34 / 50)
- `Chip` — 캡슐 태그
- `Icon` / `Serif`
- Situation 상세에서 확정된 토큰·행 관용구 — **같은 언어를 쓸 것.** 두 화면은 연속된 흐름이다

| # | 상태 | 조건 | 왜 중요한가 |
|---|---|---|---|
| 1 | **로딩** | 진입 직후 | 4개 쿼리 병렬 |
| 2 | **에러** | 쿼리 실패 | 메시지 + 재시도 |
| 3 | **갓 만든 노트** | 목표 없음 / 표현 0 / 시도 0 | ⚠️ **가장 흔한 첫 화면.** placeholder 3개가 동시에 보인다 |
| 4 | **평상시** | 목표 있음 / 표현 1~2 / 시도 2~3, 고칠 점 없음 | ⚠️ **오늘 실측 그대로.** 지금 제일 안 예쁜 상태 |
| 5 | **연습 직후 복귀** | `justPracticed` + 최신 시도 펼침 | 신규. 별도로 설계할 것 |
| 6 | **고칠 점이 쌓임** | 시도 5+, 고칠 점 여러 건 | 접기 + 최신 강조 |
| 7 | **제목·목표 중복** | Quick Note 출신 | 같은 문장이 두 번 보인다 |
| 8 | **타이핑 중** | 키보드 올라옴, CTA 숨김 | 화면의 절반이 가려진다 |
| 9 | **저장 실패** | 네트워크 끊김 | `Not saved · Retry` |
| 10 | **긴 노트** | 본문 20줄+ | 스크롤 안에서 CTA가 계속 떠 있다 |

3·4·5번이 가장 중요하다. **4번을 예쁘게 만드는 것이 이 작업의 성공 기준이다.**

## 9. 제약 (바꾸지 말 것)

- **하단 네이티브 탭바** — `expo-router` NativeTabs, Liquid Glass. 이 화면에서는 **숨겨진다.** 디자인에서 탭바를 그리지 말 것. 대신 하단 고정 CTA가 그 자리를 쓴다
- **액센트는 코발트 `#3B6EE1` 하나** (dark `#5B8AF5`). 두 번째 색을 장식으로 넣지 않는다. 디자인 파일이 테라코타로 와도 코발트로 리틴트한다
- **팔레트는 iOS 시스템** — light `#F2F2F7` / dark `#000`. `design-system/tokens.json`(웹용 웜 페이퍼)이 아니라 `apps/mobile/src/design/mobile-tokens.ts`가 모바일 소스 오브 트루스
- **다크 모드 필수**
- **제목 서체는 Newsreader(serif), 나머지는 시스템**
- **컨트롤은 항상 캡슐** (`radius 9999`), 버튼 높이는 28 / 34 / 50 셋 중 하나, 최소 탭 44×44
- **그림자는 하위픽셀 엣지 페어.** `0 4px 12px rgba(0,0,0,0.1)` 류 금지 (모티프 스펙 §4)
- **타입 스케일**: 34 / 28 / 22 / 20 / 17 / 16 / 15 / 13 / 12 / 11. 그 사이 값(16.5, 12.5 등) 쓰지 말 것
- **기준 행 높이 52pt**, 컨테이너 반경은 동심(외곽 26 → 내부 26−N)
- 화면 크기 기준 **402 × 874pt** (iPhone 17 Pro 논리 해상도)
- 사용 가능한 아이콘: `sun mic bank map book search plus play pause chev back speaker check x dots bell gear ear pen arrow sparkle upload camera photo text clip star life wave2 globe translate chat contrast clock bulb gauge calendar export help shield flask link grip` (`apps/mobile/src/design/icon.tsx`)

## 12. 결정 및 반영 (2026-09-09, `Speaking Note.html`)

디자인이 돌아와서 구현했다. §11의 열린 질문은 아래로 닫힌다.

| 열린 질문 | 결정 |
|---|---|
| 목표를 별도 층으로 둘지 | **유지.** 단 Newsreader 세리프로 — 시스템 서체 본문과 서체로 갈린다. 제목과 같은 문자열이면 숨기고 placeholder로 대체 |
| 본문 편집 어포던스 | **카드로 감싸고 우측 상단에 `Edit`.** 컨테이너 자체가 어포던스 |
| 본문 최소 높이 | **제거.** 내용에 맞춰 줄어든다 |
| 하단 CTA 형태 | **떠 있는 캡슐 + 그라디언트 frost.** 바와 헤어라인 제거 |
| 연습 직후 상태 | **아래서 올라오는 고칠 점 시트.** `Got it`으로 닫고, CTA는 `Practice again`, Previous Attempts가 Linked Phrases 위로 올라온다 |
| 고칠 점 없는 시도 목록 | **`No fix suggested` 문구 삭제.** 날짜·길이·`—`만, 고스트 한 줄이 빈 이력을 설명 |
| 저장 상태 자리 | **BackBar 우측 고정 슬롯.** 12pt, `Saved`는 2초 후 사라짐, error만 캡슐 + 탭 가능 |
| 보조 액션 칩 | **제거.** 표현 연결은 섹션 액션이, 본문 편집은 `Edit`이 한다 |

### 디자인과 다르게 간 곳

- **목표가 이탤릭이 아니다.** iOS가 두 번째 Newsreader 파일을 같은 패밀리로 묶어버려서, 이탤릭 페이스를 등록하면 앱의 모든 세리프(제목·섹션 헤더 포함)가 기울어진다. 세리프 대 시스템 서체만으로도 층은 갈리므로 정자로 둔다
- **BackBar는 공용 컴포넌트를 그대로 쓴다** (44pt, 카드 배경). 디자인은 34pt well 배경이지만, 최소 탭 44×44 제약이고 Situation 상세와 연속돼야 한다
- **섹션 헤더 상단 여백 28** (디자인 26). 공용 컴포넌트라 이미 확정된 Situation 상세와 공유한다
