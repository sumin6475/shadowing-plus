# Situation 상세 — 디자인 기획서 (뼈대)

작성 2026-09-09 · 대상 화면 `StudioSituationScreen`
목적: 이 문서 하나로 다른 도구에서 화면을 디자인할 수 있게 하는 것. 비주얼은 정하지 않고 **무엇이 들어가고 어떤 컴포넌트가 필요한지**만 서술한다.

---

## 1. 이 화면은 무엇인가

사용자가 **실제로 말해야 하는 특정 상황** 하나를 펼친 화면. 예: `ABC 회사 인터뷰 — 9월`, `실험 결과 참가자 디브리핑`.

여기서 사용자가 하는 일은 셋 중 하나다.

1. **연습을 시작한다** — 이 상황에서 말할 노트 하나를 골라 녹음으로 넘어간다.
2. **말할 것을 하나 더 적는다** — 새 Speaking Note를 만든다.
3. **준비 상태를 훑는다** — 노트가 몇 개고, 쓸 표현이 뭐가 있고, 몇 번 말해봤는지 확인한다.

1번이 가장 잦고 가장 중요하다. 화면은 1번까지의 마찰을 최소화해야 한다.

## 2. 진입 경로와 나가는 길

- **들어옴**: Studio 홈의 `Your situations` 행 → 여기 / Topics → Topic 상세의 `Situations` 행 → 여기
- **나감**: 뒤로(Topic 또는 홈) / Speaking Note 상세 / 녹음(Talk) 화면 / 전체 시도 목록

## 3. 정보 위계 (고정)

PRD가 정한 순서다. 디자인이 바뀌어도 이 순서는 유지한다.

| 순위 | 블록 | 역할 |
|---|---|---|
| 1 | **Speaking Notes** | 주 작업 단위. 화면에서 가장 큰 비중. |
| 2 | **Useful Phrases** | 보조. 이 상황에서 쓸 수 있는 표현 목록. |
| 3 | **Recent Attempts** | 조용한 이력. 탐색 대상이 아니라 참고. |

세 블록이 같은 무게로 보이면 실패다. 반대로 3번이 사라져 보여도 안 된다.

## 4. 들어가는 내용과 실제 데이터

아래 필드는 전부 지금 코드에서 실제로 내려온다. **괄호 안은 실측 주의사항**이며 디자인에 영향을 준다.

### 4.1 헤더

| 내용 | 소스 | 주의 |
|---|---|---|
| 상위 Topic 이름 | `situation.topicName` | 짧음. `Work / Study`, `Ideas` 수준 |
| 상황 제목 | `situation.title` | **한 줄을 넘을 수 있음.** 사용자가 자유 입력 |
| 설명 | `situation.description` | **비어 있을 수 있음.** 없을 때 레이아웃이 무너지면 안 됨 |
| 날짜 | `situation.eventDate` | ⚠️ **현재 항상 비어 있음.** 필드는 있지만 상황 생성 UI가 값을 안 보낸다. 디자인은 "날짜 있음/없음" 두 상태를 모두 상정할 것 |
| 노트 수 / 시도 수 | 계산값 | `0`일 수 있음 |

### 4.2 Speaking Notes

노트 한 건당 쓸 수 있는 값:

| 내용 | 소스 | 주의 |
|---|---|---|
| 제목 | `note.title` | 자유 입력, 길 수 있음 |
| 말하기 목표 | `note.goal` | 한 문장. **비어 있을 수 있음** |
| 본문 | `note.body` | 길다. 이 화면에서는 안 쓰는 게 기본 |
| 연결된 표현 수 | `note.phraseCount` | `0` 흔함 |
| 시도 수 | `note.attemptCount` | `0` 흔함 |
| 상태 | `note.status` | `active` / `unsorted` / `archived` |

- 목록은 **최신 수정순**. 정렬 UI 없음.
- 개수는 보통 1~5개. 0개도 흔하다.
- **각 노트마다 "바로 연습" 진입이 필요하다.** 현재 노트 하나만이 아니라 모든 행에서.

### 4.3 Useful Phrases

이 상황의 노트들에 연결된 표현을 중복 없이 모은 것.

| 내용 | 소스 | 주의 |
|---|---|---|
| 표현 원문 | `phrase.text` | 영어 한 문장. `What I'm trying to do is...` 정도 길이 |
| 번역 | `phrase.translation` | **비어 있을 수 있음.** 학습자 모국어(한국어만이 아님) |
| 학습 상태 | `phrase.learningStatus` | `new` / `recognizing` / `practicing` / `ready` 4단계 |

- **상태가 열(column)로 읽혀야 한다.** PRD 표현으로 "데이터베이스형 목록".
- 개수는 0~수십. 많을 때 접는 장치가 필요하다.
- 이 화면에서 표현을 편집하거나 지우지 않는다. **읽기 전용.**

### 4.4 Recent Attempts

| 내용 | 소스 | 주의 |
|---|---|---|
| 날짜 | `attempt.createdAt` | |
| 어느 노트였는지 | `attempt.noteId` → 노트 제목 | **매칭 실패 가능.** 그때는 `Free talk` |
| 길이 | `attempt.durationSeconds` | **`0`이 흔하다.** 실측에서 `0s`, `1s`가 다수 |
| 수정 제안 | `attempt.repairSuggestion` | 있음. **현재 이 화면에서 안 씀** — 노출할지는 디자인 결정 |
| 전사 텍스트 | `attempt.transcript` | 있음. 현재 안 씀 |

- 최대 10건 로드, 기본 3건 노출.
- **탭해서 상세로 가는 동선이 아직 없다.** 만들지 말지는 결정 사항.

## 5. 필요한 컴포넌트

### 5.1 새로 필요하거나 다시 정의할 것

| 컴포넌트 | 하는 일 | 필요한 상태 |
|---|---|---|
| **화면 헤더** | Topic / 제목 / 설명 / 메타 | 설명 있음·없음, 날짜 있음·없음, 제목 1줄·2줄 |
| **섹션 헤더** | 블록 제목 + 우측 액션 1개 | 액션 있음·없음 |
| **노트 행** | 제목 + 메타 + 연습 버튼 | 첫 행(강조)·나머지, 메타 있음·없음, 눌림 |
| **표현 테이블 행** | 표현 + 번역 + 상태 | 번역 있음·없음, 상태 4종 |
| **표현 상태 뱃지** | 4단계 학습 상태 | `New` / `Recognizing` / `Practicing` / `Ready` |
| **시도 행** | 날짜 + 노트명 + 길이 | 노트 매칭 실패, 길이 0 |
| **블록 비었을 때** | 안내 문구 | 3개 블록 각각 |

### 5.2 이미 있어서 그대로 쓸 것

`design-system/ios-motif-spec.md`와 `apps/mobile/src/design/ui.tsx` 기준. 재정의하지 말 것.

- `Screen` — 스크롤 컨테이너, 상단 frost, 안전영역
- `BackBar` — 뒤로 가기
- `Card` — inset grouped 컨테이너 (radius 26)
- `Pill` — 캡슐 버튼 3사이즈(28 / 34 / 50)
- `Chip` — 캡슐 태그
- `Icon` — 아이콘 세트 (사용 가능한 이름은 §7 참고)
- `Serif` — Newsreader 제목용
- `Stagger` / `EnterStagger` — 진입 애니메이션
- `QuickNoteSheet` — 새 노트 바텀시트 (이 화면에서 호출만 함)

### 5.3 화면 안에서 필요한 동작

| 동작 | 트리거 | 결과 |
|---|---|---|
| 노트 열기 | 노트 행 | Speaking Note 상세 |
| 연습 시작 | 노트 행의 연습 버튼 | 녹음 화면 |
| 새 노트 | 섹션 헤더 액션 | Quick Note 바텀시트 |
| 표현 더 보기 | 섹션 헤더 액션 | 목록 확장 |
| 시도 전체 보기 | 섹션 헤더 액션 | 전체 시도 목록 |
| 뒤로 | BackBar / 왼쪽 엣지 스와이프 | 이전 화면 |

## 6. 화면 상태 (전부 그려야 함)

| 상태 | 조건 | 비고 |
|---|---|---|
| **로딩** | 진입 직후 | 5개 쿼리 병렬. 전체 스피너 하나로 처리 중 |
| **에러** | 쿼리 실패 | 메시지 + 재시도 |
| **완전 비어 있음** | 노트 0 / 표현 0 / 시도 0 | 갓 만든 상황. **가장 흔한 첫 화면** |
| **노트만 있음** | 표현 0 / 시도 0 | 두 번째로 흔함 |
| **가득 참** | 노트 5+, 표현 20+, 시도 10 | 접기 장치 필요 |

## 7. 제약 (바꾸지 말 것)

- **하단 네이티브 탭바** — `expo-router` NativeTabs, Liquid Glass. 이 화면에서는 **숨겨진다**. 디자인에서 탭바를 그리지 말 것.
- **액센트는 코발트 `#3B6EE1` 하나.** 두 번째 색을 장식으로 넣지 않는다. (디자인 파일이 테라코타로 와도 코발트로 리틴트)
- **팔레트는 iOS 시스템** — light `#F2F2F7` / dark `#000`. `design-system/tokens.json`(웹용 웜 페이퍼)이 아니라 `apps/mobile/src/design/mobile-tokens.ts`가 모바일 소스 오브 트루스.
- **다크 모드 필수.**
- **제목 서체는 Newsreader(serif), 나머지는 시스템.**
- **컨트롤은 항상 캡슐** (`radius 9999`), 버튼 높이는 28 / 34 / 50 셋 중 하나, 최소 탭 44×44.
- **그림자는 하위픽셀 엣지 페어.** `0 4px 12px rgba(0,0,0,0.1)` 류 금지 (스펙 §4).
- 사용 가능한 아이콘 이름: `mic` `calendar` `chev` `plus` `bank` `wave2` `bulb` `chat` `pen` `link` `flask` `map` `globe` `search` `check` `x` `dots` `clock` `star` `gauge` `sparkle` (전체 목록은 `apps/mobile/src/design/icon.tsx`)

## 8. 범위 밖

- 상황 이름 변경 / 삭제 / 아카이브 / Topic 이동 — **현재 이 화면에 없음.** 넣을지는 별도 결정
- 표현 추가·편집 — Note 상세에서 함
- 시도 상세(오디오 재생, 전사 보기) — 별도 화면
- 여러 Topic에 속하는 상황 — MVP 제외
