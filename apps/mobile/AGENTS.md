# Mobile product context

Before making product, UX, content-model, naming, or AI-recommendation decisions,
read these canonical sources in order:

1. `docs/product/personal-speaking-studio-strategy.md`
2. `docs/product/speaking-world.md`
3. `docs/README.md`

Treat them as the current mobile direction unless the user explicitly revises it.
Do not use `docs/archive/` or historical journal entries as current product guidance.
`Shadowing+` and `Saylo` are working or legacy names until a new public name clears
app-store, domain, and trademark review.

# Buttons and recovery states

When adding or changing form actions, paired actions, or error/retry UI, follow
[`docs/design/button-guidelines.md`](docs/design/button-guidelines.md) and verify
those states in the running app. Single form/retry buttons fill the content
width; paired buttons share equal width.
