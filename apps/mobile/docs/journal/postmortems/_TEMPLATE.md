# Postmortem — <실패 한 줄 요약>

- **날짜**: YYYY-MM-DD
- **스텝**: <스텝/페이즈 ID>
- **심각도**: P0 (즉시) | P1 | P2

## 실패 현상
무엇이 관측됐나. 에러 메시지는 **그대로 붙여넣는다** (verbatim). 어떤 입력·상태 조합에서 나는가 (재현 조건).

```
(에러 로그 / 잘못된 출력 그대로)
```

## 가설
- **H1**: … 
- **H2**: …

## 검증 방법과 결과
각 가설을 어떻게 확인/기각했나. 어떤 계측(로그·프린트·테스트)을 추가했나.
- H1 → (결과)
- H2 → (결과)

## 근본 원인
증상이 아닌 원인. 필요하면 "왜?"를 반복해 파고든다 (5 Whys). 사람이 아니라 시스템·설계에서.

## 수정
무엇을 바꿨나.

## 지표 before / after
수정이 실제로 지표를 움직였나. (예: 해당 테스트 실패 → 통과, 지표 0.6 → 0.75)

## 재발 방지 (회귀 스위트에 추가)
프로젝트의 테스트/eval에 추가한 케이스. "다음엔 조심한다"는 액션이 아니다. 시스템 변경이어야 한다.
