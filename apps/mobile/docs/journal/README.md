# Build Journal

빌드하면서 쌓이는 증거 폴더. 명령하지 않아도 학습 동반자가 여기에 자동으로 기록한다. 나중에 돌아봤을 때 "어느 단계에서 어떻게 실패해서 고쳤는지, 어떤 설계 원칙을 배우고 적용했는지, 어떤 스킬을 썼는지"가 다 남아 있도록.

## 왜 이 폴더가 있나

세 가지 능력은 말로 주장할 수 없고 산출물로만 검증된다 (출처: `Cowork OS/wiki/raw/evidence-artifacts-guide.md`).

| 능력 | 산출물 | 이 폴더 위치 |
|---|---|---|
| Engineering judgment (트레이드오프 판단) | 설계 결정 문서 (기각한 대안 포함) | `decisions/` (ADR) |
| Product quality mindset (품질의 시스템화) | 품질 기준 + 회귀 스위트 | `quality/` (+ 프로젝트의 테스트/eval) |
| First-principles failure analysis (근본 원인 분석) | 포스트모템 | `postmortems/` |

셋은 하나의 개선 루프 — **빌드 → 측정 → 실패 → 진단 → 수정** — 의 사전·상시·사후 기록이다. 셋이 함께 쌓이면 "이 사람은 시스템을 실제로 운영해 본 사람"이라는 증거가 완성된다.

## 폴더 구조

```
docs/journal/
  README.md            ← 이 파일
  JOURNAL.md           ← 누적 학습 로그 (시간순 인덱스). 여기부터 읽는다.
  decisions/           ← ADR: 되돌리기 비싼 결정 + 기각한 대안
  postmortems/         ← 실패 → 가설 → 근본 원인 → 수정 → before/after
  quality/             ← 품질 기준(quality-bar.md) + 점검/eval 점수 스냅샷
```

## 어떻게 채워지나 (자동)

학습 동반자가 아래 순간에 **자동으로 초안을 쓰고 나에게 알린다.** 내가 "기록해줘"라고 말할 필요 없다. 규칙 전문은 프로젝트 `CLAUDE.md`의 **Auto-Journal** 섹션.

- **스텝/페이즈를 넘어가기 직전** → `JOURNAL.md`에 방금 끝낸 것 한 줄 (무엇을 만들었나 / 배운 원칙 / 쓴 스킬)
- **되돌리기 비싼 결정을 내가 정하면** → `decisions/`에 ADR 초안
- **디버깅이 필요했던 실패를 고치면** → `postmortems/`에 포스트모템 초안
- **테스트/eval을 돌리거나 품질 게이트를 통과·실패하면** → `quality/`에 점수 스냅샷

원칙: **draft + notify, 결정은 안 함.** 코드를 대신 쓰지 않고, 내가 안 정한 결정을 대신 정하지 않는다. 초안은 내가 검토하고 고친다.

## 나중에 어떻게 쓰나

- **회고**: `JOURNAL.md`를 위에서 아래로 읽으면 전체 빌드 여정이 보인다.
- **인터뷰 (Career HQ의 Dig 단계)**: ADR은 "왜 X를 썼나?", 포스트모템은 "가장 어려웠던 버그는?", quality는 "좋아지는 걸 어떻게 아나?"에 대한 이미 완성된 답변이다.
- **시작 규모**: 각 1개면 충분하다. 처음부터 체계를 만들려 하지 않는다.
