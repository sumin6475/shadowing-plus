# Postmortems — 실패 분석 기록

디버깅이 필요했던 실패를 고친 뒤 남긴다. 증상 대응("재시도했더니 됐어요")이 아니라 근본 원인 분석. 핵심 두 지점:

1. **계측 없이 수정하지 않는다.** 로그가 없으면 로그부터 추가하고 재현한다.
2. **수정 후 지표 변화까지 확인해야 완결.** "고친 것 같다"는 결론이 아니다.

**blameless**: 원인란에 사람 이름이 등장하면 실패한 포스트모템이다. 원인은 항상 시스템·프로세스·설계에서 찾는다. (개인 프로젝트라도 습관을 들인다.)

**언제 쓰나**: 에러/오작동/이상한 출력이 진단을 요구했고, 그걸 가설 세워 좁혀서 고쳤을 때. 오타 한 줄 수정처럼 진단이 없던 건 제외.

**품질과 연결**: 재발 방지 항목은 반드시 프로젝트의 회귀 스위트(테스트/eval)에 케이스로 추가한다. 이 연결이 없으면 같은 실패가 돌아온다.

**파일명**: `YYYY-MM-DD-<슬러그>.md`. 형식은 `_TEMPLATE.md` 복사.
