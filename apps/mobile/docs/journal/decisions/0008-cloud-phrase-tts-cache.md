# ADR 0008 — Phrase 발음은 캐시형 클라우드 TTS 우선

- **날짜**: 2026-08-07
- **스텝**: Phrase Bank 발음 품질 개선
- **상태**: accepted

## 맥락 (Context)
Expo `expo-speech`의 기기 내장 음성은 네트워크와 비용 없이 동작하지만 실제 iPhone에서 학습용 발음으로 쓰기에는 음질과 억양이 부족했다. Phrase는 반복 재생되므로 매 탭마다 외부 API를 호출하면 지연·비용·가용성 문제가 생긴다. OpenAI 키는 모바일 번들에 포함할 수 없고, 사용자가 소유한 표현만 생성 대상으로 제한해야 한다.

## 검토한 선택지 (Options)
1. **기기 TTS 유지** — 무료·즉시·오프라인이지만 음질이 제품 기준에 미달한다.
2. **OpenAI TTS를 매 탭 호출** — 자연스러운 음성이지만 반복 비용과 지연이 발생한다.
3. **OpenAI TTS를 첫 탭에 생성하고 비공개 R2에 캐시** — 첫 재생만 지연되고 이후에는 같은 MP3를 재사용한다. 서버·저장소 운영이 추가된다.
4. **저장 시 미리 생성** — 첫 재생도 빠르지만 한 번도 듣지 않는 표현까지 비용과 저장공간을 사용한다.

## 결정 (Decision)
**옵션 3.** `gpt-4o-mini-tts`의 `marin` 음성을 Supabase Edge Function에서 호출하고, 모델·음성·프롬프트 버전·문구 해시를 키로 사용자별 R2 MP3를 lazy-cache한다. 앱은 클라우드 음성을 우선 재생하고 네트워크/API/오디오 로딩 실패 시 기기 TTS로 폴백한다.

## 기각 이유 (판단의 증거)
- 옵션 1은 실제 사용자 청음에서 품질이 낮다고 확인됐다.
- 옵션 2는 동일 phrase 반복이라는 사용 패턴에서 낭비가 명확하다.
- 옵션 4는 베타 단계 사용량을 모르는 상태에서 불필요한 선생성을 만든다.

## 결과 (Consequences)
- 첫 재생에는 TTS 생성과 업로드 지연이 생기며 로딩 상태가 필요하다.
- API 키는 Edge Function secret에만 있고, 함수는 RLS로 소유권이 확인된 `phrase_items.id`만 읽는다.
- AI 음성임을 UI에 표시한다.
- R2의 `phrase-tts/` 객체 수명주기 정리 정책은 후속 운영 항목이다.
- **재검토 조건**: 첫 재생 p95가 학습 흐름을 방해하거나, 비용/실패율이 기준을 넘거나, `marin`보다 `cedar`/다른 공급자가 학습 발음 평가에서 유의하게 우수할 때 모델·음성·선생성 전략을 다시 비교한다.
