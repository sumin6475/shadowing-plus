# ADR 0009 — Phrase 음성은 저장 직후 prewarm하고 정상 회화 속도로 생성

- **날짜**: 2026-08-07
- **스텝**: Phrase 발음 첫 재생 지연·말투 개선
- **상태**: accepted
- **선행 결정**: [ADR 0008 — Phrase 발음은 캐시형 클라우드 TTS 우선](0008-cloud-phrase-tts-cache.md)

## 맥락 (Context)
클라우드 TTS와 R2 lazy cache는 정상 동작했지만, 새 Phrase의 첫 탭에는 생성·업로드 지연이 남았다. 실제 청음 결과 학습자용으로 늦춘 발화도 목표 사용자의 영어 수준보다 느리고 부자연스러웠다.

## 결정 (Decision)
- 새 Phrase 저장이 성공하면 동일 `phrase-tts` 함수를 background로 호출해 MP3를 미리 생성한다. 저장 완료 UI는 이 작업을 기다리지 않는다.
- prewarm 실패 시 첫 탭 lazy 생성과 기기 TTS 폴백을 그대로 유지한다.
- Phrase 상세 진입 시 signed URL을 받고 `expo-audio`가 `downloadFirst`로 미리 로드하되 자동 재생하지 않는다.
- `marin` 음성을 유지하면서 정상적인 미국식 회화 속도, 연음·축약·강세·리듬을 요청하고 학습자용 감속을 금지한다.
- 프롬프트 변경은 `phrase-pronunciation-v2` 캐시 namespace로 격리한다.

## 결과 (Consequences)
- 새로 저장한 Phrase는 듣지 않더라도 TTS 생성 비용과 R2 공간을 사용할 수 있다.
- 저장 직후 앱이 종료되거나 네트워크가 끊기면 prewarm이 끝나지 않을 수 있으나 첫 탭 경로가 복구한다.
- 상세 진입 시 소량의 네트워크·다운로드가 먼저 발생하지만 스피커 탭의 체감 대기시간이 줄어든다.
- 목록의 모든 Phrase를 일괄 선로딩하지 않아 데이터·메모리 사용을 제한한다.
- **재검토 조건**: 저장 대비 실제 재생률이 낮아 선생성 비용이 과도하거나, 정상 속도 청음에서 명료도 문제가 반복되거나, 첫 탭 p95가 여전히 목표를 넘을 때.
